# SPEC-019 工程协作与交付 · wireframes（界面设计）

[PRD 统一验收](../../docs/PRD.md#accept-spec-019) · [接口契约](../../docs/APIC.md) · [数据库设计](../../docs/DBD.md) · [架构决策](../../docs/ADR.md)

核心界面：PR 检查、发布记录与 Gitea 归档（工程界面）。这是交互草图与状态要求，不是浏览器验收证据。

主流程：feature PR → develop 检查 → release 冒烟 → main 发布 → Gitea 同 SHA 归档。

```text
┌─ 课程与角色导航 ──────────────────────────────┐
│ PR 检查、发布记录与 Gitea 归档（工程界面） │
├─ 筛选/当前状态 ───────────────────────────────┤
│ feature PR → develop 检查 → release 冒烟 → main 发布 → Gitea 同 SHA 归档。 │
└────────────────────────────────────────────────┘
```

教师只见本课管理与统计；学生只见本人获授权的已发布内容。动作提交前显示窗口、权限和版本状态；提交后显示服务器返回的结果与 ID。空样本、未开始/已截止、无权限、校验失败和服务不可用需有独立提示，不得用零分或空白页代替。移动端保持可读和键盘可操作。

此规格使用 GitHub PR/Actions 与 Gitea 的工程页面，不额外开发站内管理页；界面设计关注提交 SHA、检查状态、发布记录与回滚入口。
