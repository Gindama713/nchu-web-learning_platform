# 课堂即时投票（Poll）设计方案

> 一句话：老师在**正在进行签到的这节课**上抛一道单选/多选题，已签到的学生在手机上直接点选，
> 老师和大屏实时看到分布，投完即用。不改动现有考勤与试卷链路。

---

## 1. 目标与非目标

**目标（P1 必须做到）**

- 老师在一节「进行中的考勤任务」里发起投票：单选、多选（可限最多选几项）。
- 只有**已签到**（已到 / 迟到）的学生能投，一人一票，重复提交被拒。
- 老师端与投屏大屏**实时**看到：每项票数、占比、参与率。
- 老师可手动结束投票；考勤任务一结束，投票自动失效。

**非目标（本轮不做）**

- 不做评分/判分、不计入成绩（现有 `quizzes` 随堂测负责这件事）。
- 不做题目排版、公式、图片选项。
- 不做跨课程统计、不做历史趋势分析（P3 再说）。

**为什么不复用 `quizzes`**：`quizzes` 走的是「发布试卷 → 学生答卷（attempt）→ 评分 → 逐题统计」，
一次课堂举手投票套上 attempt 生命周期会有试卷快照、作答时限、评分状态等一堆无关状态，
而且「实时出分布」在 attempt 模型里要额外聚合。投票是**轻量、即时、不计分**的东西，值得独立一张表。
唯一复用的地方：题型命名沿用 `single` / `multiple`，与 `question_version.type` 保持一致。

---

## 2. 关键设计决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 投票挂在哪里 | 挂 `attendance_task`（不是光挂课程） | 「考勤在线的课堂」正好是任务 open 的那段时间；资格判定直接用 `attendance_participant` + `attendance_record`，不用另建"课堂"概念 |
| 谁能投 | 该任务参与者 **且** `status in (present, late)` | 人没到就不该参与表决；也让「先签到再投票」成为自然的课堂动作 |
| 一人一票怎么保证 | `UNIQUE(poll_id, student_id)` | 应用层判断会被并发绕过，唯一索引是兜底 |
| 匿名 | 默认匿名：结果只出分布；老师只能看「谁还没投」，看不到「谁投了什么」 | 课堂投票要真实意见，实名会让学生跟着"正确选项"走 |
| 学生能看到实时结果吗 | **投完之后**才显示，未投看不到 | 避免从众；老师端始终可见 |
| 关闭时机 | 手动关闭 + 任务关闭即失效（**读时判定**，不写库） | 不引入定时任务；任务本身不会重开，判定简单可靠 |
| 实时怎么做 | 轮询。老师/大屏 2s，学生 5s | 项目里没有 WebSocket/SSE；SSE 会给每个学生占一个线程，160 人撑不住 |
| 结果查询 | 聚合查询 + 1 秒进程内缓存 | 大屏 2s 一拉、学生 5s 一拉，160 人 = 约 32 rps，不能每次都扫库（SQLite 读会与写互斥） |

## 3. 数据模型（`backend/migrations/027_poll.sql`）

沿用现有迁移风格：显式 `CHECK`、部分唯一索引、不写 `ON DELETE`。

```sql
CREATE TABLE poll (
  id INTEGER PRIMARY KEY,
  course_id INTEGER NOT NULL REFERENCES course(id),
  task_id INTEGER NOT NULL REFERENCES attendance_task(id),
  title TEXT NOT NULL,
  type TEXT NOT NULL CHECK(type IN ('single','multiple')),
  max_choices INTEGER,                       -- 多选上限；NULL = 不限
  anonymous INTEGER NOT NULL DEFAULT 1 CHECK(anonymous IN (0,1)),
  status TEXT NOT NULL CHECK(status IN ('open','closed')),
  created_by INTEGER NOT NULL REFERENCES user(id),
  created_at TEXT NOT NULL,
  closed_at TEXT
);
CREATE INDEX poll_course ON poll(course_id, status);
CREATE INDEX poll_task ON poll(task_id);

CREATE TABLE poll_option (
  id INTEGER PRIMARY KEY,
  poll_id INTEGER NOT NULL REFERENCES poll(id),
  ordinal INTEGER NOT NULL CHECK(ordinal BETWEEN 1 AND 26),
  label TEXT NOT NULL,
  UNIQUE(poll_id, ordinal)
);

CREATE TABLE poll_ballot (
  id INTEGER PRIMARY KEY,
  poll_id INTEGER NOT NULL REFERENCES poll(id),
  student_id INTEGER NOT NULL REFERENCES user(id),
  submitted_at TEXT NOT NULL,
  UNIQUE(poll_id, student_id)                -- 一人一票，并发也插不进第二张
);
CREATE INDEX poll_ballot_poll ON poll_ballot(poll_id);

CREATE TABLE poll_choice (
  ballot_id INTEGER NOT NULL REFERENCES poll_ballot(id),
  option_id INTEGER NOT NULL REFERENCES poll_option(id),
  PRIMARY KEY(ballot_id, option_id)
);
CREATE INDEX poll_choice_option ON poll_choice(option_id);
```

**为什么选择与票分开两张表**：单选存一行、多选存多行，统计统一走
`SELECT option_id, COUNT(*) FROM poll_choice GROUP BY option_id`，
不用在 SQLite 里 `json_each` 拆数组（那样没法建索引，160 人规模也不优雅）。
选项最多 26 个（A–Z），符合课堂习惯。

## 4. 接口清单（`backend/apis/polls.py`）

统一 `url_prefix=/api/v1`，返回 `result(...)`，写操作走 `write()` + `audit()`。

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | `/courses/<cid>/polls` | 教师 | 发起投票。body：`task_id,title,type,options[],max_choices?,anonymous?` |
| GET | `/courses/<cid>/polls?status=open&page_size=20` | 课程成员 | 列表；学生只返回 open 的，并带 `voted` 标记 |
| GET | `/polls/<pid>` | 课程成员 | 详情：题干/选项/我的选择/`can_vote`/`reason` |
| POST | `/polls/<pid>/ballots` | 学生 | 投票。body：`option_ids[]`，成功 201 |
| GET | `/polls/<pid>/results` | 教师（学生投完后可见） | 分布 + 参与率；`unvoted` 名单只给教师 |
| POST | `/polls/<pid>/close` | 教师 | 结束投票，幂等（已关闭再调仍 200） |

**错误码**（沿用 `ApiError(status, CODE, message)`）

| code | HTTP | 场景 |
|---|---|---|
| `POLL_NOT_FOUND` | 404 | 不存在或不在本课程 |
| `POLL_CLOSED` | 409 | 已关闭 / 考勤任务已结束 |
| `ALREADY_VOTED` | 409 | 同一人第二次提交 |
| `NOT_CHECKED_IN` | 403 | 未签到（含请假/缺勤/未记录） |
| `INVALID_OPTION` | 422 | 选项不属于该投票 |
| `TOO_MANY_CHOICES` | 422 | 多选超过 `max_choices` |
| `EMPTY_CHOICE` | 422 | 一道都没选 |

**结果响应示例**

```json
{"data":{
  "poll":{"id":7,"title":"这一段流水线有几处数据冒险？","type":"single","status":"open"},
  "eligible":63, "voted":58,
  "counts":[{"option_id":11,"ordinal":1,"label":"1 处","count":30,"ratio":0.517}],
  "unvoted":[{"student_id":42,"name":"刘宇娟","student_no":"24201504"}]
}}
```
（学生视角去掉 `unvoted`，且未投票时 `counts` 为空数组，只返回 `can_vote`。）

## 5. 前端

### 教师端（考勤与学情 → 进行中任务卡片）

- 任务卡里加「发起投票」按钮 → 展开小表单：题型（单选/多选）、题干、选项（默认 4 个，可增到 8）、
  多选时给「最多选几项」。
- 投放后，卡片下方出现结果条：每项一条横向进度条 + 票数 + 占比，顶部一行
  「已投 58 / 应到 63（92%）」和「结束投票」。
- 每 2 秒拉一次 `results`；页面不可见时（`visibilitychange`）暂停轮询。

### 大屏视图（可选 P2，但演示很值）

- 结果页独立放大：题干大字 + 条形图 + 大号参与人数，适合投屏。
- 复用 `charts.js` 的条形图，不引新依赖。

### 学生端（考勤页）

- 页面顶部出现一条提示条：「老师发起了一个投票：<题干>」→ 点开弹出选项。
- 单选点一个即可提交；多选勾选后提交；提交后原地变成「已提交，等老师结束」，
  并显示当前分布（因为已投完）。
- 轮询 5 秒一次**只查 `GET /polls/<id>`**（轻量：状态 + 选项 + 我投了没），不查结果。

### 轮询预算（重要）

| 客户端 | 频率 | 请求量 |
|---|---|---|
| 教师端 1 个 | 2s | 0.5 rps |
| 大屏 1 个 | 2s | 0.5 rps |
| 学生 160 个 | 5s | 32 rps（只读轻量详情，命中结果缓存） |

学生端**不做**实时结果推送，是刻意取舍：32 rps 全部走缓存/索引查询，不碰聚合统计。

## 6. 并发与性能

- **投票写入** = 一次 `write()` 事务（`poll_ballot` 一行 + `poll_choice` 1..n 行 + `audit` 一行）。
  和签到同量级，**已有 `_begin_immediate()` 短轮询重试兜底**（今天实测 160 人同时签到 160/160 成功）。
  并发脚本按 160 人同投验证一次，确认无 503。
- **不要**在投票主链路加额外写库（例如"已读回执""浏览记录"），否则又回到"每个请求都写库"的老问题。
- **结果聚合**：`poll_choice GROUP BY option_id` 在 160×2 行规模下是微秒级，但仍加 1 秒缓存，
  键为 `poll_id`，值带 `version`（= `MAX(ballot.id)` 或票数），票数没变就复用。
- **视图**：给 `poll_ballot(poll_id)`、`poll_choice(option_id)` 建索引，避免全表扫。

## 7. 测试计划

**接口/单元（`tests/test_polls.py`，沿用 `create_app({"TESTING": True})` + `test_client`）**

1. 教师发起单选 → 已签到学生投 → 201；同一人再投 → 409 `ALREADY_VOTED`。
2. 多选超过 `max_choices` → 422 `TOO_MANY_CHOICES`；一个都不选 → 422 `EMPTY_CHOICE`。
3. 未签到（缺勤/请假/未记录）学生投 → 403 `NOT_CHECKED_IN`。
4. 非本课程学生投 → 403。
5. 考勤任务关闭后投 → 409 `POLL_CLOSED`；老师手动关闭后同样。
6. 结果统计正确：3 人投 2/1，断言 `counts`、`ratio`、`eligible`/`voted`。
7. 匿名：学生视角响应里**不含**其他学生 id/姓名；教师视角 `unvoted` 有名单但无"投了什么"。
8. 学生不能发起投票、不能关闭投票（403）。

**并发（`scripts/poll_burst.py`）**

- 160 个会话栅栏同步投同一题：断言 160×201、库中 `poll_ballot` = 160 行、
  `poll_choice` 行数 = 160×选择数、无 5xx。
- 同时教师端每 2s 拉 `results` 30 次，断言全程 200、p95 < 300ms。

**界面（`test-tmp/cdp/verify-poll.js`）**

- 教师发起 → 学生端出现提示 → 提交 → 教师端数字变化 → 结束 → 学生端变只读。

## 9. 需要你拍板的 4 件事

1. **资格**：只允许已签到的人投票？（推荐：是，人没到不参与表决）
2. **匿名**：默认匿名、老师只看参与率不看具体选择？（推荐：匿名）
3. **正确答案**：这一版要不要「老师标正确选项、投完显示对错比例」？（推荐：P2 再加，P1 先纯投票）
4. **学生可见性**：投完之后能不能看到分布？（推荐：能；未投看不到，避免从众）
