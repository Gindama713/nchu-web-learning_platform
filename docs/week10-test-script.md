# 第10周 互测脚本说明

- 小组：g24201710（计算机组成原理组，242017 班）
- 脚本：`scripts/peer_test.py`
- 依赖：Python 3 标准库（`urllib` / `http.cookiejar` / `json`），无需 `pip install` 任何第三方包

## 1 脚本做什么

按任务书规定的测试步骤，对每个被测组自动跑一遍：

1. `GET /who`：读班级、组号、组长、组员，判断被测组信息是否可公开获取。
2. `GET /help`：读模块数与接口条数，判断是否提供接口说明。
3. 教师登录：使用任务书规定的 `teacher/teacher`。
4. `GET /api/v1/courses`：取被测组课程，并建一个点到任务、拿到 6 位点到码。
5. 学生登录：使用被测组提供的 `学号/学号`，依次执行
   - 错误码签到 → 期望 `422 INVALID_ATTENDANCE_CODE`
   - 正确码签到 → 期望 `201`
   - 重复签到 → 期望不新增记录（返回同一条）
6. 关闭任务：读回 `counts{present,late,leave,absent}`，核对统计。
7. 生成报告：Markdown 报告 + 原始 JSON 日志，含每次请求的时间、账号、方法、路径、状态与耗时。

## 2 怎么用

```bash
# 一个被测组
python scripts/peer_test.py --target http://192.168.1.5:5173 --student 24201718:24201718

# 一个班所有被测组（targets.txt 每行一个地址，# 开头是注释）
python scripts/peer_test.py --targets targets.txt --student 24201718:24201718

# 只测本机，验证脚本与被测端契约一致
python scripts/peer_test.py --self --student 24201718:24201718
```

常用参数：

| 参数 | 说明 |
|---|---|
| `--target` | 被测组地址，可重复传多个 |
| `--targets` | 地址清单文件，每行一个 |
| `--self` | 追加本机 `http://127.0.0.1:5173` |
| `--teacher` | 教师账号，默认 `teacher:teacher` |
| `--student` | 学生账号 `学号:密码`；不传则跳过签到用例 |
| `--out` | 报告路径，默认 `docs/week10-test-report.md` |
| `--json` | 原始日志路径，默认与报告同名 `.json` |

## 3 两个必须知道的实现细节

**一、写请求要带 `Origin` 和 `X-CSRF-Token`。**
被测组的写接口要求请求头 `Origin` 与其站点同源、并携带登录返回的 `csrf_token`，
否则返回 `403 CSRF_FAILED`。脚本已按被测组地址自动填 `Origin`，并在登录后复用令牌。

**二、必须绕开系统代理。**
课堂地址通常是局域网 IP，本机若开着代理（公司/学校的 HTTP 代理或梯子），
`urllib` 会把请求打到代理上而不是被测组。脚本内已用 `ProxyHandler({})` 强制直连；
如果你自己另写脚本，请同样显式禁用代理。

## 4 退出码

- `0`：所有被测组结论为“通过”
- `1`：至少一组存在失败项，具体原因写在报告的“结论”一节

失败项不会中断整批测试，脚本会继续测下一组，便于一次拿到全班结果。

## 5 与原任务书测试步骤的对应

| 任务书步骤 | 脚本位置 |
|---|---|
| 首先访问 `/who` 和 `/help`，获取被测组基本信息及 API 接口说明 | `run_scenario()` 开头两步 |
| 根据获取的信息确定测试策略，完成若干次点到测试，记录访问时间、过程、结果、异常信息 | 建任务 → 错误码 → 签到 → 重复签到，全部记入 `trace` |
| 测试结束后生成测试报告，对结果做出分析与总结 | `to_markdown()` 生成汇总表、明细、访问过程与结论 |
| 上述步骤尽可能通过自动化脚本完成 | 全流程无人工干预 |
