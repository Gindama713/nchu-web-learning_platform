## 3 讲解口径（被问到时照这个说）

- **为什么不做成大模型对话？** 课程要求统计与推荐结果可复算、不能伪造数据。本实现把「理解问题」限制在固定关键词表（`assistant-rules-v1`），「回答」由模板和历史统计拼成，任何数字都能回到 010A/010B/011/014 的原口径复核。现场断网也能跑。
- **换个说法为什么也能懂？** 分类是打分制，不是「第一个关键词决定一切」：每个意图维护一组口语说法，命中词越长分越高，再给具体维度加权，「怎么样/情况/如何」这类泛词权重为 0。仓库里有约 130 条问法回归（每个意图 6—12 种说法），改规则必须让这组测试保持全绿。
- **听不懂的时候怎么办？** 给 4 个候选问题让你点，不硬猜、不拿知识检索凑答案。教师说「他/她」时会接上一位查过的学生，并显示「正在问：某某」，可随时清除。
- **和已有模块什么关系？** 助手不新建统计口径，只做入口聚合：考勤取 010A、掌握度取 010B、预警取 014、知识点检索取 011。改了这些模块的算法，助手跟着变，不会出现两套数字。
- **数据安全？** 接口只读：反复提问不写 `analysis_run`、不写业务表；学生身份只从会话取，请求里的 `student_id` 直接拒绝。动作按钮不绕过原接口的权限和幂等校验。
- **数据不足怎么办？** 直接说「算不出来」并列出缺什么，不填 0，也不换一个好看的数字。这是特性，不是缺陷。
- **图是怎么来的？** 后端只算数字，前端用项目自己的 SVG 函数画（没引图表库、没联网）。图的数据与上面的数字来自**同一次取数**，所以圆心人数一定等于「应到人次」；没数据就不画，不会出现空白框或 0% 的假图。一次回答最多两张图。
- **为什么有的问题没图？** 知识检索（「程序计数器是什么」）没有可比的数字，就只给文字和相似度；只有一周考勤数据时也不画折线——一个点画不出趋势，硬画会误导。

## 4 失败预案

| 现象 | 处理 |
|---|---|
| 点了提问没反应 | 先看浏览器是否还是旧缓存：`Ctrl+F5` 强刷；再确认后端是本次代码（`curl /api/v1/health` 有响应） |
| 回答里出现「暂不可用（DEPENDENCY_UNAVAILABLE）」 | 当前库缺测评/实验事实表，属预期降级；换课程 16 或先跑一次练习，别现场改库 |
| 所有数字都是「无数据」 | 课程没有已关闭考勤或已评分答卷；先做一次签到并关闭任务，再问 |
| 页面 404 / 500 | 查端口是否被旧进程占用：`netstat -ano | findstr :5000`，停掉旧 PID 后重启 `start-demo.bat` |
