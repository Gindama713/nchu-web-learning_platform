## 2 架构、数据与权限边界

前端为 Vue 3 组合式渲染函数，后端为 Flask RESTful API，持久层 SQLite。所有写操作先在服务端校验会话、课程成员身份与角色，再在事务内落库；前端隐藏按钮不是安全边界。课程成员关系决定数据可见范围，教师只能操作自己负责课程，学生只能读写本人尝试。

本人模块的核心数据边界有三条：

| 边界 | 规则 | 原因 |
|---|---|---|
| 实验尝试归属 | 一条 `wiring_attempt` 只属于一名学生与一个实验版本 | 统计去重与成绩归属都以该行唯一入口 |
| 实验区间归属 | 统计按实验版本 `end_at` 归入周区间，`end_at` 不得为未来 | 保证历史区间可复算，不允许未来实验提前计入 |
| 备课可见性 | 草稿仅教师可见，发布后学生可见，撤回后学生不可见但记录保留 | 避免未定稿内容被学生看到，同时保留审计 |

## 3 备课单元（SPEC-004）

备课单元解决的是「一节课的课前组织」：把知识点、资源、题目与随堂测按排期绑定成一条可发布单元。数据上由 `preparation` 主表加四张关联表组成，状态机为 `draft → published → withdrawn`。

创建与编辑：教师创建时写标题、排期与四类关联；草稿可反复修改，发布件不可直接改写，需撤回后重新发布。这样处理是因为发布动作会写学生通知，若允许原地改内容，通知所指的内容会与实际不一致。

模板复制：`POST /preparations/{id}/copy` 生成一条新草稿，复制关联但保留 `source_id` 指向原单元；原单元的发布状态、发布时刻与通知均不变。复制是本人 CP-2 的演示点，它把「按周复用同一套备课结构」变成一次服务端操作，而不是靠前端拼装。

发布与撤回：发布前校验关联随堂测均已发布，未发布返回 409 `QUIZ_NOT_PUBLISHED`；只有 `draft` 可发布，否则 409 `STATE_CONFLICT`。发布在同一事务内写 `published_at`、学生通知与审计事件；撤回写 `withdrawn_at`、理由与审计，且只允许 `published` 发起。审计的 `before/after` 记录状态变更与 `replaces_id`，便于事后追溯哪一版替代了哪一版。

需要说明的局限：排期的业务语义（第几周第几节课）目前由标题与时间字段承载，没有独立的课次实体；教师检查时若要求按教学周严格对齐，需要扩展字段，而不能靠前端显示推断。

## 4 课堂演示（SPEC-007）

课堂演示把 CPU 的取指、译码、执行过程做成教师可推进、学生可跟随的会话。状态全部在服务端，会话保存 `step`、`cycle`、`pc`、`ir`、寄存器、总线与 `ram`，前端只做渲染，不自行推算下一拍。

推进接口为 `PUT /demo-sessions/{id}/state`，携带当前 `revision`。服务端在同一事务内先比对 revision 再推进，落后方返回 409 `REVISION_CONFLICT`；会话关闭后再推进返回 409 `STATE_CONFLICT`。这样两名教师或多标签页同时操作时，只有一方的推进生效，不会出现两人各推进一拍却互相覆盖的错位。

学生端的跟随采用轮询（约 2 秒）而非推送：课程场景并发低，轮询实现简单且失败可自愈，断线重连后自然回到最新状态。代价是同步存在秒级延迟，教师连续运行时学生画面可能滞后一拍；这一点在用户说明中写明，不作为缺陷掩盖。

场景预设包含门电路、组合逻辑、时序逻辑、运算器、存储器、指令执行六类，对应 `demo_presets`。每个场景给出初始 `ram` 与寄存器，使同一套推进逻辑可复用于不同课堂主题。

整合事实：`frontend/js/demo-view.js` 在主干采用姜苏豪版本（六场景、501 行），本人同名实现与 `demo-view.test.js` 未进主干；本人保留 `demo-client.js` 承担接口契约与前端测试。本文因此只主张接口与状态机层面的设计，不把视图层代码算作已合入成果。

## 5 实验箱连线（SPEC-017，重点难点）

### 5.1 端子模型

面板由 `backend/engines/wiring.py` 的 `_make_panel(code)` 构造，包含端子表、器件与内置规则。每个端子有 `id`、`direction`（input/output）、`width`（位宽）与所属器件。连接合法性在服务端判定：必须一输出一输入、方向不可反、位宽必须相等；前端在连线时给同样的即时提示，但最终以服务端为准。

### 5.2 动作序列与重放

学生每次操作产生一条动作：`connect`（含 `id`、`from_terminal`、`to_terminal`）、`disconnect`（含 `wire_id`）、`set_input`（含 `terminal_id`、`value`）。服务端不存「画布快照」作为真值，而是存有序动作并调用 `replay(panel, actions)` 从初态重放得到 `state`，其中 `wires` 为导线列表。这样撤销/重做、断线恢复与教师回看都能复现同一过程，而不是依赖前端上传的可疑状态。

重放在 `initial_state(panel)` 上顺序执行，并维护 undo/redo 栈：`connect` 的反向是 `disconnect`，`disconnect` 的反向是把被删导线重新 `connect`，`set_input` 的反向是写回旧值。动作表 `wiring_action` 持久化每条动作与客户端时间，`wiring_attempt.state` 保存重放结果，二者可用 `GET /wiring-attempts/{id}/actions` 对照。

### 5.3 revision 冲突与提交

保存、校验、提交三处都要求客户端带上当前 `revision`，服务端在事务内比对，不匹配即 409 `REVISION_CONFLICT`。已提交的尝试再保存或再校验返回 409 `STATE_CONFLICT`，窗口外的操作返回 409 `WINDOW_CLOSED`。提交成功后写 `snapshot_hash` 与 `submitted_at`，并把功能判定结果一并保存，尝试随即变为只读。

冲突处理的设计取舍：不做「服务端自动合并动作」。学生两端同时连线时，自动合并会产出无人确认的网表，判定结果无法归责；直接拒绝并提示重新加载，代价是学生重做少量操作，收益是判定与成绩始终对应明确的一次提交。

### 5.4 功能判定

提交时按面板内置规则逐条比对期望值与实际值，结果以判定表返回，`completed` 表示全部通过。EXP-03 跑满 12 拍后 `ACC=5`、`IR=0xF0` 并停机，与本模块测试用例一致。判定只覆盖面板声明的功能点，不等同于 Logisim 的真实电路仿真；后者需要固定 JAR 与 Java，属全组评测链，本机 `grader_ready=false` 未验证。

### 5.5 教师只读

教师打开同一实验只能列出学生尝试与查看记录，不提供代做入口；列表按课程与实验版本过滤，`GET /courses/{id}/wiring-attempts` 只返回本课程数据。这条边界让「学生操作、教师查看」的课堂流程不会因权限宽松而失真。

## 6 先修知识图谱（SPEC-015）

图谱由知识点为节点、先修/包含关系为边构成。接口 `GET /courses/{id}/knowledge-graph` 返回节点、边与先修路径；`POST /courses/{id}/knowledge-edges` 新增关系。成环检测在 `backend/models/knowledge.py` 中完成，命中返回 422 `PREREQUISITE_CYCLE`——先修关系一旦成环，学习顺序不再有拓扑序，后续「推荐下一步」会失去意义，因此在写入侧直接拒绝，而不是在读取侧裁剪。

前端本人的实现（`graph-view.js`）提供聚焦根、直接关联与可达先修路径展示、加边表单，成环时把后端 422 原样呈现，作为负向用例演示。图谱后端（成环检测、迁移 015、图谱 API 与测试）经 PR #24 已合入主干；该文件与主干 `knowledge-graph-view.js`（力导向布局）是两套视图，标题重复属整合遗留，当前 `develop` 只含后者，本人视图未合入，报告中如实说明。

## 7 连线统计（SPEC-010C）

统计回答两个问题：一门课的实验有多少人真的做完，以及错误集中在哪些类型。指标为 `assigned_count`、`attempt_count`、`completed_student_count`、`completion_rate` 与 `error_counts`，并输出按周的 `period_start/period_end` 序列。

去重口径：`assigned_count` 以「实验版本 × 学生」为唯一计数，同一学生多次尝试不重复计入；`completed_student_count` 只统计提交且功能判定通过的尝试；`attempt_count` 统计尝试次数本身，用于观察反复失败。`completion_rate` 为完成人数除以应做人数，应做人数为 0 时返回 `null` 而不是 0，避免把「没人参加」误读为「无人完成」。

区间口径：实验按版本 `end_at` 归入周区间，`end_at` 不能填未来。因此一个尚未结束的实验不会出现在任何区间，查询窗口必须覆盖其结束时间。这一条在实际演示中最容易被误判为「统计坏了」，已写入用户说明与测试报告。

快照：查询结果保存为不可变快照（`analysis_run_id`），可「恢复原快照」复现同一结果，也可导出同编号 CSV。后续考勤更正或重新提交不静默改写旧快照，需要新结论就再查询生成新编号。
