## 1 项目概述

### 1.1 背景与目标

面向"数字逻辑"与"组成原理"课程，构建在线学习平台"学海通"，把课堂点到、课前备课、课堂演示、随堂测、课程知识、习题训练、实验辅助、智能问答、教学资源、统计分析与学情预警放在一个入口里。系统以中央处理器（CPU）为主线组织知识、实验与评测内容。

立项时的三条硬约束贯穿全程：

1. **数据必须真**：统计、推荐、预警、评测都读真实业务事实，不用随机图表或固定假数据冒充分析结果。
2. **规格驱动**：需求、接口、数据库、架构、变更、运行六份文档先行；代码与测试按 SPEC 编号关联，验收项可追溯。
3. **可运行**：每个模块都要能被同学在浏览器里实际操作，不能只有接口或只有截图。

### 1.2 团队与分工

四人各自负责"基础模块 + 独立统计子模块 + 智能/难点模块"，互为主审，避免一人包干。

## 2 需求分析

### 2.1 功能需求

系统共 20 个 SPEC：001—019 为任务书规定模块，020 为第 12 周教师新增的教学助手。按业务域分为五组：

| 业务域 | 模块 | 核心能力 |
|---|---|---|
| 身份与课堂 | 001、002 | 三角色注册登录、课程成员、考勤任务、数字码/手势签到、请假审批、座位与换位、即时投票 |
| 教学内容 | 003、004、005、009 | 资源上传与版本、备课单元与发布、知识章节与检索、实验指导 |
| 测评 | 006、008、013 | 五题型题库、随堂测限时判分、智能组卷与快照重放 |
| 实验与演示 | 007、017、018 | CPU 单步演示、实验箱连线仿真、Logisim 电路在线评测 |
| 数据与智能 | 010A—D、011、012、014、015、016、020 | 四类统计、检索问答、个性化推荐、学习预警、知识图谱、图片识别、教学助手 |
| 工程 | 019 | 分支保护、CI、发布与归档 |

### 2.2 非功能需求

- **权限**：所有课程数据以服务端课程成员与角色为准，前端隐藏按钮不作为安全边界；写请求校验 Origin 与 CSRF。
- **并发**：课堂高峰单班 160 人同时签到/投票，须保证一人一条记录、不重复计票、不因日志写拖垮读请求。
- **可复算**：统计结果保存不可变快照，页面与 CSV 使用同一 `analysis_run_id`，后续更正不改旧快照。
- **降级**：数据源缺失或样本不足时明确说明，不填造 0 分或假聚类。
- **可运行**：单端口即可对外服务，课堂现场不依赖前端开发服务器。

## 3 系统设计

### 3.1 技术架构

| 层 | 选型 | 说明 |
|---|---|---|
| 前端 | Vue 3 + Vite | 单页应用，按业务域分页签；图表为零依赖 SVG（`charts.js`），不引图表库 |
| 后端 | Flask + RESTful API | `backend/apis` 按 SPEC 划分 HTTP 边界，`backend/shared` 放鉴权、事务、响应 |
| 数据 | SQLite（WAL 关闭） | 单写者模型；迁移文件校验和锁定，`db-upgrade` 顺序执行 |
| 统计与智能 | pandas / NumPy / scikit-learn / OpenCV | 010A—D、011—016、020 实际使用，不接外部大模型 |
| 评测 | Logisim 5.0.0 固定 JAR | 子进程隔离，超时/内存/输出限制，固定 SHA 校验 |
| 工程 | GitHub PR + Actions，Gitea 课堂归档 | feature → develop → release → main，main 禁止直推 |

### 3.2 数据库设计

数据库共 27 个迁移版本，覆盖身份、课程、考勤、座位、投票、资源、备课、知识、题库、试卷、作答、实验、连线、评测、统计快照、访问日志等实体。关键约束：

- 考勤任务发布时复制冻结参与人名单，之后转入不补历史缺勤；
- 签到码只存哈希，创建/轮换响应各返回一次明文；
- `attendance_record` 用 `UNIQUE(task_id,student_id)` 兜住并发重复签到；
- `poll_ballot` 用 `UNIQUE(poll_id,student_id)` 兜住一人一票；
- 统计快照 `analysis_run` 保存输入、参数、结果与算法版本，发布后不可更新。

### 3.3 接口设计

接口按 APIC 分 16 节：身份/课程、考勤/资源/备课/知识、测评与演示、统计与智能、实验连线、电路评测、运维、跨模块名单、幂等、互测公开接口、专业组实验台、第 10 周补充、课堂投票、教学助手。统一约定：

- 列表接口返回 `data/total/page/page_size/request_id`，空列表 `data=[]` 而非 404；
- 写操作支持 `Idempotency-Key`，同键同内容重放原响应，不同内容 409；
- 错误统一 `{error:{code,message,details},request_id}`，不泄露堆栈与路径。

## 4 详细实现

### 4.1 身份与课堂（姜苏豪）

**用户与权限**：学生自助注册（默认密码为学号），教师与管理员只能由管理员授予；密码加盐哈希，会话带版本号，停用或改密后旧会话立即失效；课程成员是授权边界，跨课访问返回 404。

**考勤**：任务发布冻结名单，六位数字码只存哈希；签到与请假审批互斥，关闭任务才结算缺勤；教师有理由更正保留前后值与通知。

**课堂扩展**：手势签到由教师建任务时画 3×3 图案（只存哈希）；座位在发布任务时快照，学生可自助选座、向同学发起换位（15 分钟自动失效）；即时投票挂在进行中的任务上，仅已签到学生可投，一人一票，匿名时不返回逐人明细。

**统计 010A**：已关闭考勤的冻结参与人 + 已评分答卷，先算到勤率与成绩百分比，再用至少三名有效配对学生计算 Pearson 相关；不足三人、零方差分别返回原因；结果存快照，CSV 按原 ID 导出。

**预警 014**：规则（正确率 <60% 或最近两次考勤异常）与固定参数 KMeans 并列；不足 10 名完整样本时降级为规则提示；教师可标记处理，不自动处分或扣分。

**识别 016**：OpenCV 灰度 + 形态学 + 64×64 模板交并比，0.55 以下不输出、0.55—0.85 低置信、0.85 以上高置信；F01—F05 固定 PNG 与 SHA 入库；确认只存结构草稿，不进成绩。

**教学助手 020**：只读问答，意图打分制，数字复用 010A/010B/011/014 同口径；支持澄清候选与「他/她」多轮指代；教师可查单个学生到课明细与最近一次点名缺勤名单，学生可查本人成绩、做题与进度。

### 4.2 知识与测评（黄俊诚）

- **005 课程知识**：章节与知识点发布/下架、检索、收藏幂等、完成状态。
- **006 习题与测评**：五题型不可变版本、编卷发布冻结名单、按发布时答案快照判分、简答人工评分与更正、错题自动入库。
- **008 随堂测**：服务器时间截止、幂等交卷、逐题正确率与选项分布、讲评后才释放解析，截止未讲评时阻止同题所有版本的练习旁路。
- **010B**：知识点掌握度（仅实际作答、多标签去重）、分类成绩（作业/考试/随堂测，待批与缺交不混均分）、进度（当前发布集合）。
- **011 检索问答**：字符 1—3gram TF-IDF + 余弦相似度，阈值 0.10，固定别名表，返回片段与出处。
- **012 推荐**：Pandas 汇总错题与进度，按薄弱度排序，冷启动只推教师标记的基础内容，完成且掌握良好的过滤。
- **013 组卷**：候选冻结、确定性回溯、快照保存全部排序键；约束不足 422、搜索上限 503。

### 4.3 备课、演示与连线（罗浩铭）

- **004 备课**：单元关联本课知识、资源与随堂测，模板复制不改原单元，发布后学生收到预习通知，草稿不可见。
- **007 课堂演示**：教师单步推进门电路/组合时序/ALU/存储器/CPU 取指译码执行，学生页按序号跟随，刷新恢复最新状态，学生无权推进。
- **017 实验箱连线**：面板端子、连接/拆线、step/reset、RESET/ENABLE 持久化与重放；位宽/方向/悬空/重复边/不存在端子分别定位错误；结构合法但功能错不计完成。
- **010C**：实验完成率（按版本要求的全部提交方式都完成）、连线错误类型分布、尝试次数趋势。
- **015 知识图谱**：先修/包含关系维护，成环拒绝保存，邻接矩阵计算可达路径，节点状态来自真实学习数据。

### 4.4 资源、实验与评测（石佰合）

- **003 教学资源**：上传、版本、按章节/类型检索、授权下载；访问事件按 `event_id` 去重，区分预览/下载与独立人数。
- **009 实验辅助**：实验目标、器件、步骤、验证、关联知识点，跳转连线与 .circ 提交入口，显示本人历史版本。
- **018 电路在线评测**：.circ 上传校验、预检、排队、真实 Logisim 子进程执行、判分与报告、教师重评；超时/内存/输出限额分类，平台故障不扣学生分。
- **010D**：教学通过率、分数分布、系统错误/超时/限额独立统计，只取最新有效 run，排队与系统错误不覆盖旧分。

## 5 测试与质量

### 5.1 测试分层

| 层 | 规模 | 说明 |
|---|---|---|
| 后端单元/接口 | 58 个测试文件 | 覆盖身份、考勤、统计、知识、测评、组卷、实验、连线、评测、助手 |

| CI | 6 个 job | policy / lint / test / build / grader / required；develop 不跑真实评测，main 与 release 跑 |

### 5.2 已实测的关键数据

- **课堂并发**：11-13 现场 160 名学生在课；单端口发布后学生选座 200、签到返回 201。
- **轮询治理**：事故窗口 27,889 条访问、73.8% 为轮询、850 个 503；改为统一节拍器 + 自适应退避后，30 并发 × 15 轮 450 请求 0 个 5xx。
- **投票压测**：160 人同时投，160/160 成功、最慢 7.1 秒、零重复计票。
- **预警真实批次**：课程 16 生成 analysis_run 548，命中 110 人；因无到期实验版本，聚类按规格降级为规则提示。
- **教学助手**：真实库教师 6 类问题、学生 4 类问题，数字与统计页一致；越权与空数据均有测试。

### 5.3 质量门禁

- 每个 PR 必须通过 `ci-policy`（分支流向 + 文档检查）、`ci-lint`（ruff + eslint）、`ci-test`（后端 + 前端）、`ci-build`，`ci-required` 聚合；
- 文档检查 `scripts/check_docs.py` 校验六份主文档、老师目录结构与本地链接；
- 评测模块在 main/release 额外跑 `ci-grader`：下载固定 SHA 的 Logisim JAR，用 xvfb 跑真实引擎冒烟。

## 6 部署与运行

课堂与演示采用单端口发布：`SERVE_DIST=1` 时 Flask 直接托管 `frontend/dist`，一个进程对外，避免 Vite 代理导致全班共用出口撞限流。数据库为本地 SQLite，迁移由 `db-upgrade` 顺序执行；上传目录、日志与备份在源码目录之外。发布流程为：备份 → 迁移副本演练 → 迁移正式库 → 启动服务 → 冒烟 → 开放写入；失败保持维护模式并按 CHG-RB 回滚。

## 7 项目管理

- **分支**：feature/xxx → develop（保护，需 PR + 必需检查）→ release/xxx → main（保护，仅接受 release/hotfix）。
- **提交规范**：`feat(spec-00X): ...`、`fix(...)`、`test(...)`、`docs(...)`，一个提交只做一件事。
- **检查点**：CP-1 需求设计、CP-2 基础模块、CP-3 统计模块、CP-4 难点、CP-5 系统检查，材料在 `docs/checkpoints/`。
- **风险处理**：登录限流误伤、轮询风暴、SQLite 单写者、Logisim 无头运行等都在现场暴露后留了复盘文档与回归测试。

## 8 不足与改进

1. **课堂数据不完整**：课程 16 的三份试卷在截止前无人提交，010A 的非空成绩配对只有固定算例，缺少真实班级证据。
2. **识别泛化有限**：016 只验证白底黑色正向标准符号，照片、旋转、手绘不在已验证范围。
3. **评测依赖外部 JAR**：仓库不携带 Logisim JAR，本地无 Java 21 时只能降级为 `system_error`，真实引擎验证依赖 CI 或目标环境。
4. **部署仍是开发服务器**：Werkzeug 单进程 + SQLite，未上生产 WSGI；50 会话目标环境与备份恢复演练未执行。
5. **非作者评审记录不足**：GitHub 必需批准人数为 0，课程要求的实际评审记录仍需补。
