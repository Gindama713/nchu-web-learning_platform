## 演示前 15 分钟（别省，80% 的翻车都出在这）

   ```bash
   cd D:/Desktop/WebBigHomework/wt-demo
   SERVE_DIST=1 E:/Python/python.exe -m backend.app   # 已构建过 dist，不用再 npm run build
   ```
   默认只监听 `127.0.0.1:5000`，同学手机访问不到；要全班一起用，得让 Flask 监听
   `0.0.0.0`（临时改 `app.run(host="0.0.0.0")` 或用 `flask run --host 0.0.0.0`），
   并在 Windows 防火墙放行 5000 入站（**需要管理员权限，提前做**）。

2. **把网址和账号写在大屏上**：`http://<本机局域网 IP>:5000`，

3. **让同学提前登录（关键）**：登录限流是**每 IP 20 次/分钟**（实测同一 IP 连登，

4. **课程别停错**：教师端点课程卡片进 **「计算机组成原理 · 第11周课堂演示（新开课）」**（课程 16）。

> 主线一句话：「我们做的是一套能真正上课用的系统，从备课、演示、点到到学情分析都在里面。」

| 时间 | 操作 | 话术要点 |

## ② 4:00–7:00 全班点到 + 投票（全班动手）

### 4:00–5:30 点到

1. 教师：**考勤与学情** → 找到进行中的任务 → 点「轮换码」拿 6 位签到码（明文只显示这一次）。
   **码就贴在刚点的那条任务头上**（「进行中」徽标右边一个深蓝小胶囊，写着「签到码 123456」），
   换一条任务点轮换码，码会跟着搬到那条任务上，页面顶部不再占一整条横条。
   > 现在进行中的是 **#57「第11周课堂点名 · 备用（签到码）」**（#52/#53 已被关闭，别点错）。
2. 大屏念码：「请大家打开刚才的网址，登录后进考勤页，输入 **XXXXXX**。」
3. 学生：登录 → 进课程 → 考勤 → 输码 → 签到。座位图会同步标注「已到 / 迟到 / 请假 / 缺勤」。
4. 教师端边等边讲：「座位图是这节课的实况，谁到了、坐哪、什么状态一目了然。」

**并发这件事已经有结论，可以放心让大家一起点**：实测同一瞬间 60 人点，60/60 成功、
p50 1.4 秒、最慢 3 秒；160 人同时点也 160/160 成功（最慢约 10 秒）。别催，
让同学点完等一两秒即可，**不要连点**——连点只是多排一次队。

### 5:00–6:00 可选分支：空教室自助选座

如果想让全场一起动手，这是最有参与感的一段（也是「并发抢座」的现场版）：

1. 教师 → **教室设置** → 「清空座位（空教室）」→ 确认。座位表归零，学生端立刻看到一张全空的教室。
2. 大屏说：「现在教室是空的，点任意一个空位就是你的座位，坐下会直接弹出签到。」
3. 学生点空位 → 落座 → 自动弹签到面板 → 填码。
4. 讲一句：「两个人抢同一个位置，先点到的占住，后点的会提示『这个位置已经有人了』，
   不会把别人挤掉。」——这条有自动化验证：40 人抢同一格，恰好 1 人成功、39 人收到提示，
   库里只有 1 行；40 人各选一格则 40/40 全成、零重座。
5. 演示完想恢复整齐的排座：点「一键按班排座」即可。

> 顺序要点：**先清空、再开任务**，或开了任务再清空都行（清空会连进行中任务的座位快照一起清）。
> 已结束任务的座位图保留当时的历史，不会被动。

### 6:00–7:00 投票（系统内，全班一起投）

这次有真投票了，就挂在刚才那条进行中的签到任务上——**只有签到过的人能投**，这句话本身就是卖点。

**教师端（大屏，约 40 秒出题）**

1. 考勤与学情 → 卡片里「课堂投票」→ 点「**发起一场投票**」。
2. 题型选「单选题」（也可以现场切判断题——判断只有「正确/错误」两个选项，不用填）。
3. 题目填：`这段流水线有几处数据冒险？`；三个选项：`1 处` / `2 处` / `3 处`（点「+ 加一项」加第三个）。
4. 正确答案：**在「2 处」左边那个圈上点一下**（勾上就变深绿 ✓，再点取消）。
   **单选/判断只能勾一项**，点第二个会自动换过去；多选是方框，可以勾好几项。
   一个都不勾就只统计分布、不算正确率。匿名那个勾默认勾着，想让学生看到逐人明细就点掉（变成实名）。
5. 点「发起投票」。提示「已经发出去，签到过的学生几秒内会收到弹窗」。

**学生端（全班，约 30 秒）**

6. 不用切页签，**5 秒内桌面会自己弹出一个投票框**（浮层，压在页面上，签到面板开着的会等它关）。
   万一手滑点了「稍后」或者没弹出来：到「考勤与请假」下面「课堂投票」里点那一行**蓝色的「投票」**，
   浮层会重新打开——不用刷新页面。
7. 点一个选项 → 提交 → 立刻看到分布条、正确答案，以及「我选的」标记。
8. 讲一句：「同一个人投两次会被拦下——接口返回『你已经投过了』，库里只有一票（唯一约束）。」
   > **没签到的学生**：那一行给的是「去签到」而不是「投票」（状态写着「签到之后才能投票」），
   > 点了会滚到该签的那条任务并闪一下。这正是「只有签到的人能投」的可视证据。

**回到教师端（约 40 秒收口）**

9. 点这一场的「**看结果**」：分布条、参与率、正确率（对 X · 错 Y）、未投名单。
10. 实名投票会多一张**逐人明细表**（姓名 / 学号 / 所选 / 判定 / 提交时间），可以按「答对 / 答错」筛。
    160 人的课默认只铺 12 个未投名字，点「展开」才全给。
11. 讲一句：「这块是实时刷新的，学生还在投的时候数字就在动。」

> 并发已有实测：160 人同一瞬间投票，**160/160 成功**，库里 160 条 ballot 无重复，
> 对错统计 80/80 分毫不差；同一人同时点两次，一成一败（409），不会变两票。
> 最慢的一位等了约 7 秒（SQLite 单写者，串行 fsync），所以**别催，也别让学生连点**。

> 翻车预案：没弹窗 → 让他刷新一次（轮询 5 秒一次）；弹窗关了 → 让他点「稍后」之外别再等，
> 教师端照样能看结果；真想再投一遍 → 结束后重开一场，不要改库。

| 看什么 | 怎么说 |

| 课程成员 | 「161 人一个表，搜学号就直接定位。」 |
| 学情统计（出勤 × 成绩相关） | 「出勤和成绩可以放在一起看，预警是被数据推出来的，不是老师印象。」 |

**常见提问准备**：

- 「能支撑多少人？」→ 单机 SQLite，一个班 60–160 人同时操作已验证 0 失败；再大要换 PostgreSQL。
- 「签到能作弊吗？」→ 码 6 位、可随时轮换、每人一次、迟到单独标记；还有手势图案签到。
- 「数据安全？」→ 密码加盐哈希、会话 2 小时过期、写操作校验 CSRF、按角色隔离。
- 「断网怎么办？」→ 老师端可手动更正考勤（留更正理由并通知学生）。

## 翻车预案

| 现象 | 处置 |
|---|---|
| 同学打不开网址 | 先查手机是否同一 Wi-Fi；再查防火墙；最后切 4G 热点让 3–5 人示范 |
| 有人登录报「请求过多」 | 同一出口 IP 触发限流（20 次/分钟），让他等 30 秒再登，或换一个出口 |
| 点到后页面没变化 | 别刷新整页，等 2 秒；仍不动就点一次「签到」重试（重试已保证不会 503） |
| 座位图空白 | 刷新页面；仍空就切回列表视图讲，别停 |
| 学生说没看到投票弹窗 | 让他刷新一次（前端 5 秒轮询一次）；还不行说明他没签到，正好讲「只有签到的人能投」 |
| 投票点了没反应 | 别连点，等 3–7 秒（160 人同时投时最后一位要排一会儿队） |
| 投影/后端崩了 | 立刻切 `test-tmp/shots-demo/` 截图继续讲，口头承认并给出原因 |
