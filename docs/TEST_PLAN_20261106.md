## 2 自动化脚本与运行说明

现有脚本 `scripts/peer_test.py`（Python 3 标准库，无需 pip）已实现 **S01/S02/S04/S05 + F01/F02/F04 + E01**，
对每个被测组自动跑完整链路并产出 Markdown 报告 + 原始 JSON 日志。

```bash
# 1. 把课堂上公布的被测组地址写进 targets.txt，每行一个，# 开头为注释
#    http://10.83.86.162:5173
#    http://10.83.86.162:8000

# 2. 批量跑（学生账号用被测组公布的学号，密码默认等于学号）
python scripts/peer_test.py --targets targets.txt \
  --student 24201718:24201718 \
  --out docs/tests/test1/peer-report.md

# 3. 先拿本组地址自测一遍，确认脚本与被测端契约一致
python scripts/peer_test.py --self --student 24201718:24201718
```

要点：
- 脚本用 `ProxyHandler({})` **强制直连**，本机开着代理也能打到局域网地址。
- 写请求自动带同源 `Origin` 与登录后下发的 `X-CSRF-Token`，否则被测端会 403。
- 退出码 `0` 全通过 / `1` 有失败项；失败不中断，会继续测下一组。
- 报告含每次请求的时间、账号、方法、路径、状态码、耗时，可直接作为缺陷表证据。

## 3 判定标准

- **主要功能是否正确**：S01–S05 全通过且 E01 全链路 2xx、`counts` 与明细一致 → 判「正确」；
  任一核心环节失败 → 判「不正确」，并在缺陷表登记。
- 严重程度：核心链路不可用 / 数据错误 = 高；异常分支返回码不符 = 中；文案、样式 = 低。
- 接口失败不重复记缺陷，合并成一条并列出所有受影响参数。
